# 安装与兼容性

## 环境要求

安装前确认以下版本完全匹配：

| 组件 | 要求 |
| --- | --- |
| Minecraft | 1.21.1、1.21.4 或 26.2 |
| NeoForge | 使用与 Minecraft 构建对应的版本 |
| Java | 21 |
| Command Block Studio | 两端均可选；允许版本不同，服务端增强按可用接口启用 |

!!! warning "不要混用加载器"
    本模组是 NeoForge 原生实现。Fabric、Forge 旧版或通过兼容层加载不在支持范围内。

## 客户端安装

1. 在[版本选择](../releases/versions.md)中确认 Minecraft 与 NeoForge 的对应关系。
2. 将 `command_block_studio-<模组版本>-<Minecraft版本>-NeoForge.jar` 放入游戏实例的 `mods` 目录。
3. 使用 Java 21 启动游戏。
4. 在模组列表中确认 **Command Block Studio** 已加载。
5. 进入有命令方块编辑权限的世界，打开命令方块进行验证。

客户端安装已经包含编辑器、补全、文档、诊断、工作区页签、粒子预览和本地配置。

其他模组的命令不需要额外兼容层。Studio 直接读取服务器 Brigadier 命令树，并为一组常见模组提供可选说明与注册表预览；详细范围见[模组命令软兼容](../guide/mod-compatibility.md)。

## 服务端安装

服务端安装不是编辑器运行的前提。只有需要以下能力时才需要服务端也安装：

- 在命令方块中保存和同步共享注释。
- 在工作区页签中请求服务端刷新目标命令方块数据。

服务端安装步骤：

1. 停止服务器。
2. 将同版本 JAR 放入服务端 `mods` 目录。
3. 确认服务器使用 Java 21 和当前 Minecraft 构建对应的 NeoForge。
4. 启动服务器并检查日志中没有依赖或网络载荷注册错误。

## 双向非必须

Command Block Studio 不要求连接双方拥有相同的模组列表。网络载荷使用 NeoForge 原生可选协商，支持以下四种组合：

| 客户端 | 服务端 | 结果 |
| --- | --- | --- |
| 已安装 | 未安装 | Studio 编辑器、补全、文档和本地工作区正常使用；共享注释与服务端历史入口隐藏 |
| 未安装 | 已安装 | 玩家使用原版命令方块界面并可正常连接；服务端仍可记录原版客户端提交的命令方块编辑历史 |
| 已安装 | 已安装 | 启用完整编辑器，以及共享注释、版本化编辑记录和增强工作区同步 |
| 未安装 | 未安装 | 保持原版行为 |

只有在双端都安装时才会协商 Studio 自定义载荷。任意一端未安装都不会因为缺少载荷通道而被踢出服务器。服务端单独安装不会把 Studio 界面发送给原版客户端，也不会要求玩家下载模组。

## 更新与卸载

更新时先关闭游戏或服务器，再替换旧 JAR。不要同时保留两个版本。

卸载客户端模组不会修改已经写入命令方块的命令。服务端共享注释保存在命令方块持久化数据中；卸载服务端模组后不会显示，也不会参与原版命令执行。
